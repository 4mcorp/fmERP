## 목표
기능은 없지만 다음이 되는 빈 골격을 만든다.
- `pnpm install` → `pnpm dev`로 web(`/api/health`)과 worker가 함께 뜬다.
- `pnpm lint`, `pnpm typecheck`, `pnpm test`가 통과하고 CI도 통과한다.
- 에이전트용 hooks·LSP가 적용되어 이후 마일스톤에서 바로 기능 개발을 시작할 수 있다.

## 범위
- **포함:** 모노레포 구조(TECH_SPEC 4장), 로컬 Docker 환경, DB 연결·마이그레이션 체계, S3 어댑터(FILE-001), Hono + OpenAPI 골격(API-001), 품질 도구, CI, ADR 4건, Claude hooks·LSP·권한 설정
- **제외:** 인증, 도메인 테이블, 화면 기능(M1부터)

## 환경 확인 결과 (2026-10-03)
- Node **24.14.0** 설치됨 → 최신 LTS 패치 **24.21** 업데이트 권장 (같은 메이저)
- corepack 0.34.6 → `corepack enable`로 pnpm 11.28.3을 사용
- Docker 29.6.1, Compose 5.2.0 설치됨
- **MinIO는 GitHub 저장소가 보관(archived) 처리됨** → 로컬 S3 대체재가 필요 (결정 P2)

## 단계
- [ ] **1. 개발 환경:** Node 24.21 업데이트, `corepack enable`, `.nvmrc`
- [ ] **2. 루트 설정**
  - `package.json`: `engines`, `packageManager`, 공통 스크립트(`dev`, `build`, `lint`, `typecheck`, `test`, `db:*`)
  - `pnpm-workspace.yaml`: `strictPeerDependencies`, `autoInstallPeers: false`, `allowBuilds`
  - `tsconfig.base.json`, `biome.json`, `.env.example`, `renovate.json`
- [ ] **3. 패키지 골격**
  - `packages/core`, `db`, `auth`, `storage`: 각 패키지의 package.json, tsconfig, `src/index.ts`, Vitest 설정
  - 의존 방향은 Biome `noRestrictedImports`로 강제한다. 예: core에서 db·pg·hono import 금지 (rules/architecture.md 1장)
- [ ] **4. 로컬 Docker 환경** (`docker-compose.dev.yml`)
  - PostgreSQL 18: 개발 DB + 테스트 DB. 초기 SQL로 `ltree`·`pg_trgm` 확장과 앱·마이그레이션 계정을 분리 생성
  - 로컬 S3 (결정 P2)
  - Mailpit: 개발용 메일 수신함 (이메일 알림 확인용)
- [ ] **5. packages/db:** `drizzle.config.ts`, `pg` 풀 클라이언트, 첫 마이그레이션(확장, 계정 권한 기본값), `db:generate`·`db:migrate` 스크립트
- [ ] **6. packages/storage**
  - 인터페이스: `put`, `putIfAbsent`(write-once), `get`, `head`, `presignGet`, `presignPut`
  - S3 구현 + 로컬 S3 대상 통합 테스트. `putIfAbsent`가 기존 키를 덮어쓰지 않는지 검증
- [ ] **7. apps/web**
  - Next 16.3 (App Router, TS, Tailwind 4), shadcn 초기화(Radix)
  - Hono를 `/api`에 마운트하고 `/api/health`(DB 연결 확인)와 `/api/doc`(OpenAPI) 제공
  - Zod로 검증하는 `env` 모듈
- [ ] **8. apps/worker:** pg-boss 시작, 예시 예약 작업(heartbeat), `@hono/node-server` 헬스체크
- [ ] **9. ADR 작성** (`docs/adr/`, 결정 P1 반영)
- [ ] **10. Git 품질 관문:** lefthook — pre-commit에서 변경 파일 Biome 검사, commit-msg에서 commitlint(rules/git.md의 type·scope)
- [ ] **11. Claude 하네스**
  - `.claude/settings.json` hooks: Edit·Write 후 해당 파일 Biome 포맷 (결정 P4)
  - typescript-lsp 플러그인 활성화
  - 읽기 전용·검증 명령 허용 목록 (`pnpm lint/typecheck/test`, `git status/diff/log`)
  - `playwright-cli`를 devDependency로 설치
- [ ] **12. CI** (`.github/workflows/ci.yml`)

## 결정 필요
| # | 항목 | 제안 | 이유 |
|---|---|---|---|
| **P1-a** | 기본 키 | **UUID v7** — PostgreSQL 18 내장 `uuidv7()` 사용 | 시간순 정렬로 인덱스 효율이 좋고, ID를 추측할 수 없으며, 이관·병합 시 충돌이 없음 |
| **P1-b** | 금액 | DB `bigint`(원), 앱에서는 `number` + 안전 정수 범위 검증 | 원화 정수만 쓰고 9천조 원 미만이면 `number`로 충분 |
| **P1-c** | API 에러 형식 | **RFC 9457 Problem Details** (`application/problem+json`) + 업무 오류 코드 필드 | 표준이고 OpenAPI 문서화가 쉬움 |
| **P1-d** | 통합 테스트 DB | Docker Compose의 테스트 전용 PostgreSQL 18(메모리 기반 tmpfs) + 테스트 실행마다 새로 마이그레이션 | 별도 라이브러리 없이 CI 서비스 컨테이너와 같은 방식 |
| **P2** | 로컬 S3 (MinIO 대체) | **SeaweedFS** (Apache-2.0, Docker 풀 수 2,800만+) / 대안 RustFS (Apache-2.0, 최신) | 운영은 R2·S3이고 로컬은 S3 API 호환만 필요. 오래 쓰인 SeaweedFS가 안정적. 결정되면 TECH_SPEC·PRD FILE-001·DEPLOYMENT_PLAN의 MinIO 언급을 수정 |
| **P3** | Git hook 도구 | **lefthook + commitlint** | 단일 바이너리라 Windows·CI에서 빠르고, Biome·commitlint 연동이 단순함 |
| **P4** | Claude hooks 범위 | Edit·Write 후 **포맷만** 자동 실행. 타입 검사는 작업 종료 시 에이전트가 직접 실행 (CLAUDE.md 5단계) | 매 종료마다 전체 타입 검사를 hook으로 돌리면 느리고 토큰 소모가 큼 |
