## 범위
M8 변경분: 알림 테이블·DB 함수(0018~0021), 텔레그램 연결·수신(폴링/웹훅)·발송, 알림 API, 수신 방식 설정, 운영 알림, 스테이징 `APP_ENV` 예외, 스테이징 Compose. 직접 코드를 읽어 점검했고 `differential-review`·`semgrep` 스킬은 돌리지 않았다.

## 지적과 조치
| # | 내용 | 조치 |
|---|---|---|
| S1 | `notification_pending_events`(SECURITY DEFINER)가 계정을 가로질러 이벤트 `payload`를 돌려줬다. 반려 의견·결재선 변경 사유가 들어 있어, 앱 코드가 뚫리면 다른 회사의 의견 내용을 읽는 경로가 된다 | 함수는 id·계정·문서·종류만 돌려주고, 내용은 worker가 테넌트를 지정해 RLS 아래에서 읽는다 (0021, 시험으로 열 이름 고정) |
| S2 | 텔레그램 **연결 요청**만 감사 로그에 남고, 연결이 **완료**된 것(알림이 가는 곳이 바뀐 순간)은 남지 않았다 | `notification.telegram_linked` 기록 추가 (시험 포함) |
| S3 | 로그·시스템 설정 화면에 DB 오류 메시지가 그대로 남아 SQL 매개변수(토큰 해시, 대화 번호)가, 네트워크 오류에는 요청 주소(봇 토큰)가 실릴 수 있었다 | `safeErrorText`로 이름·코드·첫 줄만 남긴다 (단위 시험 포함). Bot API 클라이언트는 처음부터 메서드·상태만 담았다 |

## 점검했고 문제가 없었던 것
- **테넌트 격리:** 알림은 `account_id` + RLS, 본인 알림만 조회·읽음(남의 알림·다른 회사 알림은 404, 시험 있음). 알림 이동 경로 `href`는 서버가 종류와 문서 UUID로 만들어 열린 리다이렉트가 없다.
- **웹훅:** 비밀 헤더를 상수 시간으로 비교하고 틀리면 404. 업데이트 하나가 실패해도 200을 돌려 재전송 폭주를 막는다. 개인 대화·봇 발신이 아닌 `/start <토큰>`만 처리한다.
- **연결 토큰:** 24바이트 난수, DB에는 SHA-256 해시만, 10분 만료·1회용, 새 토큰 발급 시 이전 토큰 무효. 대화 하나는 한 사용자에게만 묶인다.
- **외부 문구:** 텔레그램 문구에는 문서 제목·본문·반려 의견·변경 사유가 들어가지 않는다(단위 시험).
- **권한:** 수신 방식 변경은 시스템 관리자 + PIN 재인증 + 감사 로그, 웹훅은 공개 https 주소와 비밀 값이 없으면 409. 텔레그램 연결·토큰 테이블은 `fmerp_auth`만 접근한다.

## 남긴 위험과 후속 과제
| # | 내용 | 비고 |
|---|---|---|
| FU-M8-1 | **`APP_ENV=staging` 예외**는 테스트 로그인이 켜진 서버가 Cloudflare Access 뒤에 있다는 가정에 기댄다. 운영 `.env`에 실수로 `APP_ENV=staging`·`DEV_TEST_LOGIN=true`가 들어가면 누구나 시드 계정으로 로그인할 수 있다 | 사용자가 예외를 승인했다(2026-10-06). 운영 compose 작성 때 두 변수가 없는지 점검 항목에 넣고, M9의 "테스트 로그인 비활성화 확인"에서 운영 응답으로 직접 확인한다 |
| FU-M8-2 | 연결 링크(`t.me/…?start=토큰`)가 유출되면 10분 안에 먼저 연 사람이 그 사용자의 알림 수신처가 된다. 알림 문구에 문서 제목은 없지만 기안자 이름·문서 링크는 간다 | 짧은 만료와 1회용으로 줄였다. 필요하면 연결 때 PIN 재인증을 요구한다 |
| FU-M8-3 | 웹훅은 요청 본문 검증(400)이 비밀 헤더 검사보다 먼저라서, 비밀을 모르는 사람도 형식이 틀린 요청에 400을 받고 경로가 있음을 안다 | 영향 작음. Cloudflare 속도 제한 규칙(DEPLOYMENT_PLAN 7장)에 이 경로를 넣는다 |
| FU-M8-4 | 텔레그램은 외부 서비스라 기안자 이름이 문구에 들어간다 | 계획에서 합의한 범위. 더 줄이려면 계정 설정으로 "이름 없음"을 둘 수 있다 |
| FU-M8-5 | 웹 서버와 worker 둘 다 봇 토큰을 읽는다(웹은 웹훅 답장용) | 웹훅을 쓰지 않으면 웹의 토큰을 뺄 수 있다. 운영에서 폴링만 쓰기로 하면 웹에서 제거 |
