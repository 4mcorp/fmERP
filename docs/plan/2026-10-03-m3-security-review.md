## 범위와 한계
- 대상: packages/core 결재 엔진·결재선·대결·채번, 마이그레이션 0005·0006, apps/web/server/approval·routes/approvals.ts.
- 직접 코드를 읽고 통합 테스트로 재현해 확인한 **자체 리뷰**다. `differential-review` 스킬·Semgrep은 실행하지 않았다.
- 결재 처리 API·화면(M4), 열람 권한(M5)은 아직 없어 범위 밖이다.

## 점검한 경로와 결과
| 경로 | 결과 | 근거 |
|---|---|---|
| 처리자가 아닌 사람의 처리, 차례가 아닌 단계 처리 | 차단 | 엔진 `not_assignee`·`step_not_active`, 통합 테스트 |
| 완료·취소·보관 문서의 본문·결재선 변조 (API·DB 직접 쓰기) | 차단 | 트리거 `document_before_update`·`approval_step_guard`, 통합 테스트(후결 승인만 예외) |
| 상신 후 문서 내용 수정, 상신 문서 삭제 | 차단 | 같은 트리거 |
| 처리 기록·이벤트 변조·삭제 | 차단 | UPDATE·DELETE 권한 없음 |
| 같은 단계 동시 처리, 원 결재자·대결자 동시 처리 | 한쪽만 반영 | 문서 행 `FOR UPDATE` + 단계 version, 통합 테스트 |
| 병렬 그룹 동시 처리로 인한 갱신 손실 | 차단 | 문서 행 잠금으로 직렬화, 통합 테스트 |
| 같은 요청 재시도(멱등) | 한 번만 처리 | `(step, 멱등 키)` 유일, 통합 테스트 |
| 문서번호 중복·누락 | 차단 | 시리즈 행 한 문장 증가, 병렬 100건·롤백 테스트 |
| 연쇄 위임, 퇴사자 대결자, 본인 위임 | 차단 | core 검증 + 서비스 검증 |
| **기안자의 권한 상승**: API에서 `canFinalize`(전결)·`policy`·`numbering`을 직접 지정 | **수정함** | 입력에서 받지 않도록 제한(전결은 위임전결 규정 P1, 정책·번호는 양식 M4가 정함), 통합 테스트 |
| 다른 계정 문서 접근 | 차단 | RLS, `not_found` |
| 관리자·소유자·감사인의 결재 문서 열람 | 참여자가 아니면 404 | PRD 3.3 각주 1, 통합 테스트 (감사인·공람 열람은 M5 PERM-003) |
| 부재 설정 후 이미 차례가 온 단계 | **수정함** | 설정·취소 때 활성 단계의 대결자 재계산 (APV-052) |

## 후속 과제
| ID | 심각도 | 내용 | 처리 시점 |
|---|---|---|---|
| FU-11 | 중간 | 서비스는 호출자가 넘긴 처리자(`membershipId`)와 `isApprovalAdmin`을 신뢰한다. 처리 API는 세션에서 구성원을 도출하고, 결재 관리자 여부를 서버가 판정하며, 결재 PIN 재인증(AUTH-009)을 거쳐야 한다 | M4 (처리 API) |
| FU-12 | 중간 | 지금은 기안자가 결재선을 자유롭게 지정한다(후결 단계로 결재자를 돌려 완료를 앞당기는 구성 포함). 양식 기본 결재선·수정 허용 여부(APV-004·033)와 후결 사용 규칙으로 제한해야 한다 | M4 |
| FU-13 | 낮음 | 진행 중 결재선 변경(APV-037)은 단계 트리거가 막고 있다. 변경 전용 경로와 트리거 예외를 함께 추가해야 한다 | M4 |
| FU-14 | 낮음 | 거부된 처리(권한 없음 등)는 감사 로그에 남기지 않는다. 업무 거부 기록 범위를 정한다 | M6 |
| FU-15 | 정보 | `approval_event` outbox에 소비자가 없고 `processed_at`도 없다. 소비자를 만들 때 열을 추가한다 | M5·M8 |
