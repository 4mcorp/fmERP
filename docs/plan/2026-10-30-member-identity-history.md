## 목표
- 관리자가 구성원의 이름·메일을 바꿀 수 있다.
- 바뀐 뒤에도 과거 이름으로 같은 사람임을 알 수 있다 (불변 사번 + 변경 이력).
- 양식 `user` 필드를 이름 / 이름+메일 / 사번으로 표시할 수 있다.

## 결정
- 사번: `P` + 4자리 일련번호, `P0000`부터 1씩 증가. 계정(account) 단위 채번. 사업자 슬러그·코드와 무관(슬러그는 바뀔 수 있어 접두어로 쓰지 않는다).
- 사번은 한 번 부여하면 불변이고 재사용하지 않는다. 관리자도 수정 불가. 기존 수동 입력 UI는 읽기 전용으로 바꾼다.
- 기존에 입력된 `membership.employee_no`는 유지한다. NULL인 구성원만 마이그레이션에서 `created_at` 순으로 채번한다. (기존 값이 `P####` 형식과 겹치면 건너뛰고 다음 번호를 쓴다.)
- 문서 본문은 `membershipId`만 저장하므로 `contentHash`는 이름 변경과 무관하다. 화면은 현재 이름을 조회한다.
- 완료 패키지(`final/` PDF·manifest)는 완료 시점의 이름·사번으로 고정한다. 이미 쓴 파일은 바꾸지 않는다.
- 이름 변경 이력은 추가만 가능한 테이블에 쌓는다(`audit_log`와 같은 원칙).

## 범위
- 포함: 사번 채번, 이름·메일 수정 API/UI(관리자), 변경 이력 테이블, 시점별 이름 조회("과거이름 (현재: 현재이름)"), 과거 이름 검색, `user` 필드 표시 옵션, PDF에 완료 시점 이름·사번 반영.
- 제외: 소셜 로그인 연동 시 이메일 동기화(M9), 사번 형식 변경.
- 미결: `user.email`은 Better Auth 로그인 식별자이므로 변경 시 세션·인증 영향 확인 필요(구현 1단계에서 검증).

## 완료 기준
- 통합 테스트: 사번이 `P0000`부터 중복 없이 증가(동시 생성 포함), 이름 변경 후 이력 조회·과거 이름 검색, 이전 `contentHash` 불변.
- `pnpm lint`, `pnpm typecheck`, `pnpm test:unit`, `pnpm test:int`, `pnpm arch:check` 통과.

## 결정·변경 기록
- 2026-10-30: 사번 접두어를 사업자 코드에서 고정 `P`로 변경(사업자 슬러그가 변경 가능하므로).
- 2026-10-30: 사번 채번·불변은 앱 코드가 아닌 DB 트리거로 구현(Better Auth·시드 등 멤버십 생성 경로가 여럿이라서). 다른 회사에도 속한 사용자의 이름·메일은 한 회사 관리자가 바꿀 수 없다(409).
