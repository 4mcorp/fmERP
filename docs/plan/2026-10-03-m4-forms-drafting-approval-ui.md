## 목표
사용자가 **양식을 골라 기안하고, 결재선을 지정해 상신하고, 모바일에서도 결재를 처리**할 수 있게 M3 엔진 위에 화면과 처리 API를 올린다. 동시에 M3·M1 보안 리뷰의 후속 과제(FU-1·2·11~13)를 해소한다.

## 범위
- **포함 (P0):** APV-001, 003~007, 010~017, 019, 033, 036, 037, 042, 043, 048, 052, BAK-001, FILE-002, FILE-004, FILE-005(이미지·PDF), ADM-004
- **함께 처리:** M3 후속 FU-11(처리 API는 세션에서 처리자 도출 + 재인증)·FU-12(양식 기본 결재선·후결 제한)·FU-13(진행 중 결재선 변경 경로), M1 후속 FU-1·2(업로드 크기·형식 검증, 미등록 객체 정리), 문서 본문의 S3 리비전 이동(BAK-002, 불변 조건 "본문은 S3, DB는 색인")
- **제외:** 결재 PDF·완료 패키지·수신·공람·문서함 전체·검색(M5), 감사인 열람(M5·M6), 알림(M8), 계산 필드·조건부 결재선·위임전결 규정표(P1), 거래처 선택(3차), 오피스 문서 미리보기(P1), 악성코드 검사(P1)
- 문서함은 **결재 대기**와 **기안함(임시저장·회수·반려 포함)** 두 개만 만든다(처리에 꼭 필요). 나머지 문서함은 M5.

## 설계

### 1. 양식 (APV-001~007, ADM-004)
| 테이블 | 핵심 |
|---|---|
| `form` | account_id, code(계정 안 고유), name, category(분류), active, 사용 범위(사업자·부서 jsonb, 비면 전체), current_version_id |
| `form_version` | form_id, version, `schema`(필드 목록 jsonb), `layout`(용지, 결재란 위치, 로고·직인 위치), 기본 결재선(템플릿 참조), 문서번호 규칙, 보존연한(1·3·5·10년·영구), 보안 등급 기본값, 참조·수신 기본값, 결재선 수정 허용 여부, 결재 정책(합의 부동의·반려 대상·감사 반려) — **불변**(트리거로 UPDATE·DELETE 거부) |
| `approval_line_template` | 양식별 기본 결재선(공용) 또는 개인 즐겨찾기(소유자 지정), 항목은 M3 `DraftLineItem[]` + 단계 잠금 표시 |
| `user_form_pref` | 사용자별 즐겨찾기·최근 사용 (APV-010) |

- **필드 유형(MVP, D8):** 텍스트, 여러 줄, 숫자, 금액(원, 정수), 날짜, 기간, 단일·다중 선택, 사용자 선택, 부서 선택, **표(행 추가 + 열 합계)**, 리치 텍스트 본문, 첨부. 필수·기본값·최소/최대·정규식 검증. 자유 배치는 하지 않는다.
- **검증은 `packages/core`의 순수 함수**(`form-schema.ts`: 양식 스키마 검증, `form-values.ts`: 입력값 검증·표 합계)로 한다. 서버와 화면이 같은 함수를 쓴다. (core에 외부 의존성을 추가하지 않는다.)
- **기본 양식 7종**(일반 기안, 품의서, 지출결의서, 휴가신청서, 출장신청서·보고서, 업무협조전, 구매요청서)은 `packages/core`의 데이터로 정의하고, **계정 생성 때 자동 등록**한다. 기존 계정은 시드·보정 스크립트로 채운다.
- 수정하면 새 버전이 된다. 이미 작성된 문서는 `document.form_version_id`로 작성 당시 버전을 렌더링한다. 복제, 사용 중지, JSON 가져오기·내보내기를 제공한다.

### 2. 문서 본문과 리비전 (BAK-002, 불변 조건)
- 본문(양식 입력값)은 **S3 `docs/{계정}/{사업자코드}/{YYYY}/{문서ID}/revisions/{n}.json`에 저장할 때마다 새 키**로 쓴다. DB `document`에서 `body` 열을 빼고 `document_revision`(문서, n, S3 키, SHA-256, 저장자, 크기, 시각)과 `latest_revision`만 둔다. (운영 데이터가 없는 지금 한 번에 바꾼다 — ADR 0008)
- 임시저장: 수동 저장 + **30초 자동 저장**(서버), 브라우저 **Dexie(IndexedDB) 사본**(사용자·계정별, 로그아웃 시 삭제)과 복구 여부 확인 (APV-011, BAK-001). 동시 편집 충돌은 `latest_revision` 기대값으로 감지한다.
- 상신 시 **내용 해시**(본문 최신 리비전 SHA-256 + 첨부 SHA-256 목록 + 제목)를 `document.content_hash`와 처리 기록의 `doc_hash`에 남기고, 처리할 때 최신 리비전이 상신 해시와 같은지 확인한다 (APV-016). 상신 후 리비전 추가는 막는다(M3 트리거를 새 열에 맞게 조정).
- APV-090 모듈 연동의 `body`도 서버가 리비전 1로 저장한다.

### 3. 첨부 (APV-013, FILE-002·004·005, M1 FU-1·2)
- 업로드: ① 서버가 **크기를 서명에 고정한 PUT 서명 URL**을 발급(`_staging/{계정}/{uuid}`, 선언 크기 = 서명된 Content-Length) → ② 브라우저가 직접 업로드 → ③ 서버가 등록 요청에서 **객체 크기 확인, 앞부분 읽어 실제 형식(매직 바이트) 검증, 전체 읽어 SHA-256 계산** 후 최종 키 `.../attachments/{파일ID}_{원본파일명}`으로 **복사**하고 `attachment` 행을 만든다. 등록되지 않은 `_staging/` 객체는 **버킷 수명 주기 규칙(1일)** 으로 지운다(앱 키에는 삭제 권한이 없다).
- 한도: 파일당 기본 50MB·문서당 300MB(계정 정책 `attachmentMaxMb`), 허용 확장자 정책(계정 설정, M2에서 저장만 했던 값 적용). 확장자와 실제 형식이 다르면 거부한다.
- 다운로드·미리보기: 권한 확인 후 **짧은 수명 서명 URL**만 발급. 미리보기는 이미지·PDF만(브라우저 기본 뷰어). 응답 헤더로 `Content-Disposition`·`nosniff`를 지정한다.
- 서명·도장·직인 업로드(M1·M2)도 같은 방식으로 바꿔 FU-1·2를 닫는다.
- `packages/storage`에 복사·범위 읽기·스트림 읽기·크기 고정 서명 메서드를 추가한다(S3 SDK는 이 패키지 밖에서 쓰지 않는다).

### 4. 기안·결재선 (APV-010~017, 033, 036, FU-12)
- 문서 속성: 기안 소속(겸직 선택), 제목, 본문, 보안 등급(일반·대외비·비밀), 긴급, 희망 완료일, 관련 문서 링크(`document_link`, 열람 권한이 있는 문서만, APV-014).
- **결재선 규칙(FU-12):** 양식이 결재선 수정을 **허용하지 않으면** 서버가 양식 기본 결재선을 쓰고 클라이언트 결재선은 무시한다. **허용하면** 자유롭게 지정하되 **후결 단계는 양식 기본 결재선에 있는 것만** 허용한다(후결로 결재자를 돌려 완료를 앞당기는 구성 방지). 전결 권한·정책·문서번호 규칙은 양식이 정한다(M3 리뷰에서 API 입력을 막았던 항목을 양식에서 공급).
- 결재선 템플릿(양식 기본, 개인 즐겨찾기)을 불러오고 저장한다. 결재선 화면: 조직도 트리에서 사용자·부서 선택, **순서 변경은 끌어놓기(`@dnd-kit`) + 위·아래 버튼**, 단계 유형 전환, 병렬 그룹·정족수, 결재란 미리보기, 검증 오류·경고 표시 (APV-015·036·038).
- 상신 전 검증: 필수 필드, 결재선(M3 검증), 첨부 용량, 양식 버전 사용 가능 여부.

### 5. 결재 처리 API·재인증 (APV-040~043, FU-11)
| 경로 | 내용 |
|---|---|
| `POST /api/approvals/:id/steps/:stepId/act` | 승인·반려·보류·보류 해제·전결·동의·부동의·감사 행위·후결 승인. **세션에서 구성원 도출**, 결재 관리자 여부는 서버가 판정, 멱등 키·기대 version 필수, 재인증 필요 |
| `POST /api/approvals/:id/withdraw`, `/reopen`, `/redraft`, `/submit` | 회수·초안 복귀·재기안·상신 (M3 서비스 연결) |
| `POST /api/approvals/:id/comments` | 의견 추가·공개 범위(결재선 전체 / 기안자만, APV-042). `approval_comment` 추가 전용 테이블 |
| `PUT /api/approvals/:id/line` | 진행 중 결재선 변경 (APV-037): **현재 처리자 또는 결재 관리자**, 양식이 허용할 때, 아직 처리 전(PENDING) 이후 단계만 추가·삭제, **사유 필수**, 감사 로그. core에 `editLine` 순수 함수(TDD)를 추가하고 DB 트리거는 "진행 중 PENDING 단계의 추가·삭제"만 예외로 둔다 (FU-13) |
| `GET /api/inbox/pending`, `GET /api/inbox/drafts` | 결재 대기, 기안함 (APV-080 일부) |

- **재인증(AUTH-009·APV-043):** 처리 요청은 세션의 PIN 확인 시각이 유효(기본 30분, 계정 정책 `pinRequired=false`이면 생략)해야 한다. 아니면 428과 함께 PIN 입력을 요구하고, 화면은 PIN 대화상자를 띄운다(이메일 링크만으로 결재 금지, NTF-006).
- 열람 권한(M4): 기안자 + 결재선 참여자(대결자 포함). 감사인·공람·수신은 M5(PERM-003).

  - **첨부:** 선언 크기와 다른 업로드·한도 초과·허용 외 확장자·확장자 위장(PDF로 위장한 실행 파일)·미등록 `_staging` 객체는 등록 거부, 정상 첨부는 SHA-256·키 기록, 다운로드는 권한 확인 후 서명 URL, 타인 문서 첨부 접근 거부
  - **결재선 규칙(FU-12):** 수정 불가 양식은 기본 결재선 강제, 수정 허용 양식에서 후결 추가 거부
  - **처리 API(FU-11):** 세션 사용자만 처리(처리자 위조 불가), 결재 관리자 판정은 서버, 재인증 없으면 428, 멱등 키 재요청 동일 결과, 오래된 version 충돌 409
  - **결재선 변경(FU-13):** 처리자·결재 관리자만, 처리된 단계 변경 거부, 사유 필수, 감사 로그
  - **의견:** 공개 범위(기안자만)가 결재선 다른 참여자에게 보이지 않음
  - **테넌트 격리:** 신규 테이블 전부, 다른 계정 문서·양식·첨부 접근 불가
  - M2·M3 기존 통합 테스트 회귀 없음
