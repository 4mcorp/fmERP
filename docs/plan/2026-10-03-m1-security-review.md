- **대상:** M1 미커밋 변경 전체 — packages/auth, packages/audit, packages/db(스키마, 마이그레이션 0001·0002), apps/web/server(http.ts, routes/*), docker/postgres/initdb/01-roles.sh
- **분류:** HIGH (인증, 세션, 권한, 감사 로그). 규모는 MEDIUM(약 40개 파일) → FOCUSED 전략
- **한계:**

- **신뢰도:** 중간~높음. 지적 사항은 모두 통합 테스트로 재현·검증했다.

## 점검한 공격 경로와 결과

|---|---|---|

| 시드에 없는 이메일 가입·로그인 | 차단됨 | `disableSignUp`, `/api/dev/login` 허용 목록 (통합 테스트) |

| 다른 회사 데이터 조회·쓰기 | 차단됨 | RLS + `withTenant`, 테넌트 미지정 시 0행, 교차 테넌트 쓰기 거부 (통합 테스트) |

| 세션 장기 유지 | 차단됨 | 유휴 2시간·절대 12시간, 만료 시 세션 삭제 (통합 테스트) |
| 타인 서명·도장 이미지 등록 | 차단됨 | S3 키 접두사가 본인 경로인지 확인 |
| 비로그인 접근 | 차단됨 | 보호 API 11개 401 (통합 테스트, 이번 리뷰에서 추가) |

## 지적 사항과 조치
| ID | 심각도 | 내용 | 조치 |
|---|---|---|---|
| **SR-1** | 중간 | 감사 로그·Better Auth가 `X-Forwarded-For`를 믿어, 운영에서 클라이언트가 접속 IP를 위조할 수 있었다 (접속 기록은 법정 필수 항목) | 운영에서는 Cloudflare가 덮어쓰는 `CF-Connecting-IP`만 믿도록 `trustedIpHeaders()`로 통일. 헤더 값 길이도 200자로 제한 |
| **SR-2** | 낮음 | 우리 API에 Origin 검사가 없었다. 현재도 SameSite 쿠키와 JSON 전용 API로 막히지만 이중 방어가 없음 | `requireSameOrigin` 미들웨어 추가. 교차 출처 상태 변경 요청 403 (통합 테스트) |
| **SR-3** | 낮음 | API 요청 본문 크기 제한 없음 | `bodyLimit` 1MB, 초과 시 413 (통합 테스트) |
| **SR-4** | 낮음 | 로그인 실패 기록에 입력 이메일을 길이 제한 없이 저장 | 254자로 자름 |
| SR-5 | 정보 | 비로그인 접근·일반 구성원 권한 상승 테스트 누락 | 통합 테스트 추가 |

## 후속 과제 (M1 범위 밖, 해당 마일스톤에서 처리)
| ID | 심각도 | 내용 | 처리 시점 |
|---|---|---|---|
| FU-1 | 중간 | 서명 URL 업로드(PUT)에 크기 제한이 없어 큰 파일을 올릴 수 있다. 등록 시 2MB 검사는 하지만 등록하지 않은 객체가 남는다 | **M4 (FILE-002)**: 크기 제한이 있는 업로드 방식(Presigned POST의 content-length-range 등) 검토, 미등록 객체 수명 주기 정리 |
| FU-2 | 낮음 | 이미지 형식을 Content-Type 헤더로만 확인하고 실제 파일 내용(매직 바이트)은 보지 않는다 | **M4 (FILE-002)** |
| FU-3 | 낮음 | 소유자 두 명이 동시에 서로를 비활성화하면 마지막 소유자 검사를 둘 다 통과할 수 있다 (경쟁 조건) | M2 조직 관리에서 구성원 행 잠금 적용 |
| FU-4 | 정보 | 로그인한 사용자는 회사를 제한 없이 만들 수 있다 | 판매 형태(PRD Q1) 결정 후 `organizationLimit` 검토 |
| FU-5 | 정보 | 로그인 속도 제한이 메모리 저장소라 서버 재시작 시 초기화된다 | 서버 1대 구성에서는 수용. 이중화 시 DB 저장소로 전환 |
