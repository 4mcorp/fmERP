## 범위와 한계
- 대상: M6 변경분 36개 파일(`b917572..HEAD` 코드), 특히 `apps/web/server/audit/*`, `routes/audit.ts`, `approval/access.ts`(열람 기록), `packages/core/src/audit-*.ts`, 마이그레이션 0013·0014, 관리 화면·문서 상세.
- `differential-review` 방법(위험 분류 → 제거된 보안 코드 확인 → 호출자 범위 → 적대적 시나리오 → 재현)을 따랐다. 위험 분류: 권한 판정·감사 로그 노출·DB 권한은 **높음**, 화면은 **낮음**. 모델 서브에이전트(adversarial-modeler)와 Semgrep은 실행하지 않았고, 시나리오는 직접 만들어 통합 테스트로 재현했다.
- **제거된 보안 코드: 없음.** 기존 파일에서 지워진 줄은 `requireView`의 `canView` 호출(같은 판정을 인라인으로 옮김), 커서 함수의 `export` 추가, 새 인자 전달뿐이다. `requireView` 호출 지점은 9곳(첨부·의견·패키지·문서 상세·본문·양식 등)이고 모두 읽기 경로다.
- 테스트 없이 바뀐 곳: 없음(아래 모든 항목에 통합·단위 테스트가 있다).

## 발견과 조치
| # | 위험 | 내용 | 조치 |
|---|---|---|---|
| S1 | **중간** | **관리자가 문서 내용을 감사 로그로 볼 수 있었다.** 관리자(`audit.read`)는 PRD 3.3 각주 1에 따라 문서 본문을 열람할 수 없는데, 감사 로그의 `targetLabel`에는 문서 제목·첨부 파일명이, `reason`에는 반려·보류 **의견 원문**이 들어 있어 `GET /api/audit-logs`로 모든 문서(대외비 포함)의 제목·의견을 읽을 수 있었다. 재현: 통합 테스트(관리자 응답에 제목·의견 포함) | **수정함.** 문서·첨부를 대상으로 한 행의 `targetLabel`·`reason`을 `document.read_all`(계정 범위: 소유자·계정 감사인)이 없으면 `null`로 가리고 `masked: true`로 표시. 누가·언제·무엇을·IP는 그대로 보인다. 화면에 안내 표시. 통합·E2E 테스트 |
| S2 | 낮음 | **타임라인이 기안자 전용 의견의 존재를 알렸다.** `approval.comment` 로그(작성자·시각)가 이력에 나와, 참조자·감사인이 "누군가 기안자에게만 하는 의견을 남겼다"는 사실을 알 수 있었다 | **수정함.** 타임라인에서 의견 등록을 뺐다(의견 자체는 의견 영역에서 공개 범위대로 보인다). 단위·통합 테스트 |
| S3 | 낮음 | **결재자 이관 사유가 모든 열람자에게 보였다.** 이관 사유는 "병가 인수인계" 같은 인사 사정일 수 있는데 타임라인에서 문서 열람자 전원(참조·공람 포함)에게 나왔다 | **수정함.** 이관 항목의 사유는 감사 권한자에게만 보인다(누가·언제 이관했는지는 보임). 단위 테스트 |
| S4 | 낮음 | **인쇄 기록 호출로 추가 전용 로그를 부풀릴 수 있었다.** 열람 가능한 아무나 `POST /print-log`를 반복하면 삭제할 수 없는 감사 로그에 무제한으로 쌓이고(저장 낭비, 실제 사건을 묻는 소음) 서버에 요청 속도 제한이 없다(grep 확인) | **수정함.** 같은 사용자·문서는 5초 안에 한 건만 기록(advisory lock으로 동시 요청도 직렬화). 통합 테스트(동시 10건 → 1건) |
| S0 | 중간(기능) | 감사 열람 기록이 화면의 동시 API 호출에서 중복(4건)되던 경합 | 개발 중 수정함 ([ts](../ts/2026-10-05-audit-view-race-and-concurrent-int-runs.md)) |

## 남은 위험·후속
- **요청 속도 제한 부재(전반):** 서버 API 전체에 속도 제한이 없다(로그인·PIN은 Better Auth·PIN 잠금이 담당, PRD NFR-S06). 쓰기 경로 중 감사 로그를 쌓는 곳은 S4에서 막았으나, 다른 쓰기 API의 범람은 M8 운영 설정(Cloudflare 규칙 포함)에서 다룬다. → 후속 **FU-M6-1**
- **목록·검색의 메타데이터 열람 미기록:** 감사인이 감사함·검색에서 제목·기안자·문서번호를 훑는 것은 `audit_view`로 남지 않는다. 문서를 열면 남는다. 전 문서 열람 기록은 AUD-028(P1). → 후속 **FU-M6-2**
- **감사 로그 `reason`의 다른 자유 입력:** 문서 대상이 아닌 행(구성원·부서·권한 변경)의 `reason`·`diff`는 관리자에게 그대로 보인다(감사 목적상 의도). 새 행위를 추가할 때 `reason`에 개인정보·문서 내용을 넣지 않는다 → 규칙으로 `security.md`에 추가.
- 요청 속도·대량 조회로 인한 성능 저하는 측정하지 않았다(30만 건 단건 조회만 측정).
- 타임라인은 감사 로그를 최대 500건까지만 읽는다(문서 한 건에 500건 넘는 로그가 쌓이는 경우는 가정하지 않음).
