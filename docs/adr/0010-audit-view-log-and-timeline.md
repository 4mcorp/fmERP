# 감사인 열람은 근거가 `read_all` 하나일 때만 10분 중복 억제로 기록, 이력 타임라인은 `approval_action`을 정본으로 병합, 월간 점검은 추가 전용 테이블

- **열람 기록(AUD-010):** `requireView`가 열람 근거를 판정할 때 `hasReadAll`을 끈 판정도 통과하면(= 참여자·참조·수신·공람 같은 다른 근거가 있으면) 기록하지 않고, **`read_all`(감사인·소유자) 하나뿐이면 `document.audit_view`를 기록**한다. 모든 읽기 경로(상세·본문·의견·첨부·타임라인·패키지)가 `requireView`를 거치므로 한 곳에서 기록한다.
- **중복 억제:** 같은 사용자·문서는 **10분 안에 한 건**. 로그는 UPDATE할 수 없어 `occurred_at`을 조회로 판정한다. 화면 하나가 여러 API를 **동시에** 부르면 "확인 후 기록"이 겹쳐 중복되므로(10건 재현), `pg_advisory_xact_lock(hash(사용자:문서))`으로 직렬화한다. 락은 트랜잭션이 끝나면 풀린다.
- **타임라인(AUD-011):** 데이터 출처가 `approval_action`·`approval_event`·`audit_log` 셋이라 같은 사건이 겹친다. **단계 처리(승인·반려·보류·전결·합의·감사·후결)는 `approval_action`이 정본**(대결 정보가 있다)이고 감사 로그의 `approval.<처리>`는 제외한다. 완료는 `approval_event.completed`, 그 밖의 문서 행위(작성·상신·회수·결재선 변경·이관·내려받기·인쇄·공람·접수·배부)는 감사 로그에서 가져온다. 병합 규칙은 `packages/core/src/audit-timeline.ts`(순수 함수)다. 첨부 로그는 대상이 첨부 ID라 문서에 연결되지 않아 넣지 않는다.
- **노출 범위:** 접속지(IP)와 `document.audit_view`는 감사 권한자(`audit.read` 또는 `document.read_all`을 어느 범위에서든 가진 사람)에게만 보인다.
- **감사 로그 조회(AUD-025):** 계정 범위 `audit.read`(소유자·관리자·계정 범위 감사인)만. 사업자·부서 범위 감사인은 해당 범위 문서의 타임라인만 본다. 첫 쪽 조회는 `audit.view_log`로 기록한다. 보존(AUD-024)은 **삭제·아카이브 코드를 두지 않는 영구 보관**으로 충족한다.
- **감사 단계 대상(AUD-001):** 감사 단계의 처리자는 모두 **`auditor` 역할 보유자**여야 한다(범위 무관). PRD의 "감사 부서"는 부서에 감사 표시를 두는 스키마가 없어 지원하지 않는다.
- **월간 점검(AUD-026):** `audit_review`(INSERT·SELECT만, RLS). 같은 달에 여러 건이 가능하고 마지막 건이 현재 상태다. 점검 대상은 KST 기준 직전 달이고 `reviewStatuses`/`reviewTargetPeriod`(core)가 판정한다. 알림 발송은 M8.
- **인쇄 기록(AUD-020):** 화면의 인쇄 버튼이 `POST /approvals/{id}/print-log`로 기록한 뒤 인쇄하고, `beforeprint`는 최선 노력으로 같은 호출을 한다(5초 안 중복 제외). Ctrl+P 우회 일부와 화면 캡처는 기록할 수 없다.

**Considered Options:** 열람을 모든 경로에서 매번 기록(새로고침마다 쌓여 조회가 불가능해짐), 중복 억제를 별도 캐시 테이블로(UPDATE·상태 추가), 타임라인용 별도 이벤트 테이블(이중 기록과 불일치 위험), 감사 부서 표시 열 추가(범위 밖, 감사인 역할로 충분), 인쇄를 서버가 PDF 발급으로 갈음(진행 중 문서는 PDF가 없음).
