# 양식 구조는 블록 편집기 하나로 편집하고 값·불변 버전 계약은 유지한다

## 배경

구 필드 목록과 별도 입력/출력 미리보기는 같은 항목을 두 번 찾아야 했다. 기존 문서의 값과 완료 패키지를 바꾸지 않고 레이아웃 블록·다중 열·초안 자동 저장을 제공한다.

## 결정

- 관리자의 구조 편집 진입점은 `FormBlockEditor` 하나다. 구 목록과 관리자 입력/출력 미리보기, 전용 샘플 HTML 생성기는 제거한다. `FieldEditor`는 NodeView의 인라인 설정으로만 쓰며 필드 key는 수정하지 않는다. 슬래시·드래그·위/아래 버튼으로 구조를 바꾼다. ADR 0008의 기본 끌어놓기 선택은 이 편집기에서는 Tiptap 공식 drag-handle로 대체한다.
- `FormSchema.fields`의 평면 값 계약은 유지한다. 배치는 `form_version.layout.blocks`에 저장하고 서버 `validateFormLayout`으로 참조 누락·중복·열/개수/텍스트 제한을 검사한다. blocks 없는 기존 버전은 읽을 때 파생하며 UPDATE하지 않는다. 기존 일반 필드 50% 폭·wide 전폭 배치도 유지한다.
- Tiptap 문서에는 key 참조를 두고 필드 정의는 fields에 둔다. Tiptap은 구조 편집에서만 사용한다. 작성은 기존 값 위젯, 조회는 읽기 전용 어댑터로 공통 `renderBlocks`/`FormBlocks`를 사용한다. `form-fields.tsx`·`form-view.tsx`는 이 어댑터이므로 삭제하지 않는다. 표 행 추가·삭제는 값 편집이다.
- `form_draft`는 account RLS·양식/작성자 복합 FK·작성자별 유일성·revision CAS로 보호한다. 자동 저장은 초안만 갱신하고 명시적 저장만 새 불변 버전을 만든다. 공개 후 초안을 삭제하거나 revision을 초기화하지 않는다. 409는 자동 재시도하지 않고 사본 복사/다시 불러오기를 제공한다.
- Tiptap은 승인된 `~3.31.4`를 유지한다. drag-handle 필수 협업 peer는 설치하되 Y.Doc·provider·실시간 협업은 활성화하지 않는다. 구 UI 제거로 직접 소비가 사라지는 의존성은 없다. 미사용 여부는 Knip으로 검증한다.
- 웹과 PDF는 같은 Pretendard 바이트와 블록 CSS를 쓴다. 문서 크롬은 편집 불가다. 화면은 라이트 고정, 모바일은 reflow하고 columns/표만 내부 스크롤한다. 공식 출력은 서버 PDF이며 기존 완료 PDF는 재생성하지 않는다. 상신 문서의 출력 미리보기 API/모달은 별개 기능이므로 유지한다.
- 페이지 가이드는 12mm 보수 여유(세로257/가로170mm)의 CSS 근사다. 서버 PDF 여백은 바꾸지 않는다. 수동 쪽 나눔을 제공하고 한 쪽보다 큰 블록의 강제 분할을 허용한다. 모든 문서의 페이지 일치·픽셀 동일성을 보장하지 않는다.

## 대안과 영향

- 구 편집기 병행은 사용자가 거부했다. 관리자 페이지의 별도 미리보기도 남기지 않는다.
- fields 자체를 블록 트리로 바꾸면 값 검증·색인·기존 문서 계약까지 달라지므로 채택하지 않는다.
- Tiptap을 작성/조회에도 마운트하면 불필요한 구조 편집 경로가 생기므로 값 어댑터만 연결한다.
- 실제 OS 한글 IME와 실기 터치/드래그는 자동화로 검증했다고 주장하지 않는다. 사용자 확인 필요 항목으로 남긴다.
