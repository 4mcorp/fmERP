# 문서 본문은 S3 리비전, 첨부는 staging 검증 후 복사, 양식은 불변 버전, 상신 시 내용 해시를 남긴다

- **본문(양식 입력값)은 S3**: `docs/{계정}/{사업자코드}/{YYYY}/{문서ID}/revisions/{n}.json`에 저장할 때마다 **새 키**로 쓴다(덮어쓰지 않음). DB에는 `document_revision`(문서, n, S3 키, SHA-256, 크기, 저장자, 시각)과 `document.latest_revision`만 둔다. M3의 `document.body` 열은 제거한다 — 운영 데이터가 없어 한 번에 바꾼다(database.md의 expand→contract는 운영 이후부터 적용).
- **상신 후 리비전 추가 금지**, 회수한 초안에서만 추가한다. 상신할 때 `content_hash = SHA-256(최신 리비전 해시 + 첨부 해시 목록 + 제목)`을 `document.content_hash`에 남기고, 결재 처리 때 최신 리비전이 상신 해시와 같은지 확인한다(APV-016, 변조 감지). 처리 기록의 `doc_hash`에도 같은 값을 남긴다.
- **첨부 업로드**: 서버가 **크기를 서명에 고정한 PUT 서명 URL**을 `_staging/{계정}/{uuid}`로 발급한다 → 브라우저가 직접 업로드 → 등록 요청에서 서버가 객체 크기·실제 형식(매직 바이트)·SHA-256을 확인하고 최종 키 `.../attachments/{파일ID}_{원본파일명}`로 **복사**한 뒤 `attachment` 행을 만든다. 등록되지 않은 `_staging/` 객체는 버킷 수명 주기 규칙(1일)으로 지운다(앱 키에는 삭제 권한이 없다). M1 서명·도장·M2 직인 업로드도 같은 방식으로 바꿔 M1 FU-1·2를 닫는다.
- **양식은 불변 버전**: `form_version`은 UPDATE·DELETE를 트리거로 막고, 수정은 새 버전이다. 문서는 `form_version_id`로 작성 당시 스키마를 따른다. 양식 입력값 검증은 `packages/core`의 순수 함수(서버·화면 공용)이며 외부 라이브러리를 쓰지 않는다.
- **결재선 규칙(M3 FU-12)**: 양식이 결재선 수정을 허용하지 않으면 기본 결재선을 강제하고, 허용하면 자유 지정하되 후결 단계는 기본 결재선에 있는 것만 허용한다. 전결 권한·정책·문서번호 규칙은 양식이 정한다.
- **재인증(M3 FU-11)**: 결재 처리는 세션에서 처리자를 도출하고, 결재 관리자 여부는 서버가 판정하며, 세션의 PIN 확인 시각이 유효(기본 30분, 계정 정책으로 끔)해야 한다.
- **패키지**: 양식 편집기의 끌어놓기 정렬은 `@dnd-kit`(마지막 배포 2024-12, 12개월 기준 미충족)을 쓰지 않고, M2 조직 화면과 같은 방식(브라우저 기본 끌어놓기 + 위·아래 버튼)으로 구현한다. 추가하는 패키지는 `react-hook-form`·`@hookform/resolvers`·`@tiptap/*`·`dexie`(모두 최근 배포, MIT·Apache-2.0).

**Considered Options:** 본문을 DB jsonb에 유지하고 S3에는 완료 시 한 번만 복사(불변 조건 "본문은 S3"와 어긋남, 진행 중 문서가 서버 장애에 노출), 서명 POST로 크기 제한(`@aws-sdk/s3-presigned-post` 추가 필요), 업로드 후 즉시 최종 키에 쓰기(검증 전 객체가 최종 경로에 남음), `@dnd-kit`(유지보수 중단 의심).
