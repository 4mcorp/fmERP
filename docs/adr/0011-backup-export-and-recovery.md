# DB 덤프는 시스템 관리자만·서버에는 공개키만, 계정 내보내기는 소유자(허용 시 관리자)·worker가 스트리밍, 복구는 패키지 형식 v2의 `restore` 블록으로 색인 재구성

- **덤프 주체(M7 Q1):** DB 덤프에는 **모든 계정의 데이터**가 들어가므로 계정 소유자에게 열지 않는다. 환경 변수 `SYSTEM_ADMIN_EMAILS`에 있고 **이메일이 인증된** 사용자만(`isSystemAdmin`, core)이 `/api/system/*`를 쓴다. 아니면 존재를 알리지 않는다(404). 요청·다운로드·삭제는 항상 PIN 재인증을 요구한다(계정 정책 `pinRequired`로 면제할 수 없다). 파일럿(단일 회사)은 소유자 이메일을 넣는다.
- **암호화와 키(Q10):** `pg_dump -Fc` 출력을 **age(`age-encryption`, 스트림)로 암호화**한다. worker에는 **공개키(`BACKUP_AGE_RECIPIENTS`)만** 있고 개인키는 운영자가 서버 밖에 2부 보관한다. 서버가 뚫려도 덤프를 열 수 없고, 시스템 관리자가 내려받는 파일도 암호문이다. `session`·`verification` 테이블 **데이터는 덤프에서 뺀다**(토큰 유출 위험을 줄이고 복원에 필요 없음, Q11). `pgboss` 스키마도 뺀다.
- **백업 전용 DB 역할 `fmerp_backup`:** `LOGIN BYPASSRLS` + `pg_read_all_data`(읽기 전용)이고, 쓰기는 마이그레이션이 부여하는 `system_backup`·`backup_job`의 상태 갱신뿐이다(DDL·업무 데이터 쓰기 권한 없음). 계정 데이터는 코드에서 **앱 역할(RLS)로 읽어** 실수로 다른 계정이 섞이는 일을 DB가 한 번 더 막는다. 이 역할은 슈퍼유저만 만들 수 있어 initdb 스크립트에 두고, 기존 볼륨에는 직접 적용한다([ts](../ts/2026-10-05-backup-role-existing-volume.md)).
- **이력 테이블 분리(Q4):** PRD의 `backup_job` 한 테이블을 둘로 나눈다. **`system_backup`**(덤프, 계정 없음, RLS 없음, 앱 접근은 시스템 관리자 경로 한 곳)과 **`backup_job`**(계정 내보내기, `account_id` + RLS). 둘 다 끝난 행은 트리거로 고정하고(덤프는 삭제 표시만, 내보내기는 만료로만 변경) 누구에게도 DELETE 권한이 없다. 덤프는 전체에서, 내보내기는 계정마다 **동시에 하나만**(부분 고유 인덱스).
- **덤프 실행:** worker가 매일 03:00 KST에 자동 실행하고, 수동은 웹이 요청 행(QUEUED)을 남기면 worker가 5초 주기로 집는다(web에는 pg-boss가 없다, M5 결정). 순서는 pg_dump → 암호화 → 임시 파일(크기·SHA-256) → S3 멀티파트 업로드 → **올라간 객체를 다시 해시해 검증**이다. pg_dump가 도중에 실패하면 잘린 덤프가 정상 파일처럼 암호화되므로 **종료 코드를 반드시 확인**한다. 시작할 때 중단돼 RUNNING으로 남은 덤프는 실패로 닫는다. 켜질 때 기한(03:30) 안에 성공한 덤프가 없으면 바로 한 번 실행한다. 일요일 자동 덤프는 `weekly/`로 복사한다.
- **변경 없으면 건너뜀:** 변경 토큰 = `pg_stat_user_tables`(public, `system_backup`·`session`·`verification` 제외)의 삽입·수정·삭제 합. 직전 덤프의 토큰과 **같을 때만** 건너뛴다(모르거나 줄었으면 덤프). 덤프가 남기는 감사 로그가 다음 토큰에 섞이지 않게 **감사 로그를 쓴 같은 연결에서 `pg_stat_force_next_flush()`** 한 뒤 토큰을 읽는다(그러지 않으면 통계가 늦게 반영돼 영영 건너뛰지 못한다).
- **보관·삭제(Q2·Q3):** 앱 키에 삭제 권한이 없으므로(BAK-004) 일 7개·주 4개는 **버킷 수명 주기 규칙**(`daily/` 7일, `weekly/` 28일)으로 정리한다. 수동 덤프 "삭제"는 객체에 **태그 `expire=1`을 붙이고** 이력에 표시하며(그 뒤 내려받기 불가), 수명 주기 규칙이 태그가 붙은 객체를 1일 뒤 지운다. 규칙 적용은 배포 단계이고 로컬 SeaweedFS에는 없다.
- **계정 내보내기(Q5~Q7):** 소유자, 또는 소유자가 `securityPolicy.allowAdminExport`로 허용한 계정 관리자(소유자만 바꿀 수 있다). 권한을 먼저 확인하고(403) 재인증을 요구한다(428). worker가 ZIP을 **스트리밍으로 만들어** `exports/{계정}/{작업}.zip`에 올린다(읽기는 앱 역할 RLS). 내용: READY 완료 패키지가 있는 **완료 문서만**(`final/`·첨부, 그 밖은 건수만 manifest에), 조직·양식·감사 로그(JSON·CSV, 서명·도장·직인 키 제외), `manifest.json`(모든 파일의 경로·크기·SHA-256). CSV는 수식 주입을 막는다. 파일은 **7일 보관**하고 받을 때마다 **PIN 재인증 + 10분짜리 서명 URL**을 발급한다(PRD의 "7일 유효 URL"은 유출 시 7일간 누구나 받는 링크라 발급 단위를 짧게 했다). 비밀번호 암호화(선택)는 이번에 제외했다(스택 밖 라이브러리 필요).
- **패키지 형식 v2와 색인 재구성(Q8):** `approval.json`(schemaVersion **2**)에 DB를 다시 만드는 데 필요한 `restore` 블록(계정·사업자·양식 버전·정책·번호 규칙·기안자 스냅샷·생성 시각·단계별 처리자 ID·대결자·스냅샷·버전)을 담는다. `reindexAccount`는 S3 `docs/{계정}/**/final/manifest.json`을 훑어 **DB에 없는 문서**만 되살린다: manifest의 모든 파일·첨부 해시 검증 → **앱 역할로 초안 → 진행 중 → 완료 순서**로 재생성(불변 트리거를 우회하지 않는다) → 패키지 READY·검색 색인·금액·**문서번호 시리즈 보정**(`parseDocNumberSeq`로 번호에서 순번을 되읽어 `greatest`로 올림). 이미 있는 문서는 건너뛰고(멱등), 해시·형식(v1)·참조(사업자·구성원·양식이 DB에 없음) 문제가 있는 문서는 **건드리지 않고 이유와 함께 보고**한다. 드라이런을 지원한다.
- **복원·리허설(운영자 CLI):** `backup:restore`(복호화 스트림 → `pg_restore --exit-on-error`, 대상 DB가 비어 있어야 함), `backup:rehearse`(임시 DB 복원 → 표별 행 수를 운영 DB와 비교 → 무작위 완료 패키지 20건 해시 검증 → 임시 DB 삭제), `backup:reindex`, `backup:dump`(배포 직전). 개인키는 파일로 받고 서버·로그·저장소에 남기지 않는다.
- **알림:** 덤프 실패 알림 **발송**은 M8. M7은 상태(`backupHealth`: 가장 최근 03:30 기한 안의 성공·건너뜀·수동 덤프가 있는지)와 화면 경고까지.

**알려진 한계:** ① **후결 승인은 S3 `post-approvals/`에 기록하는 코드가 아직 없어**(키 규칙만 있다), DB를 잃으면 후결 승인 사실은 덤프의 감사 로그·결재 기록에만 남는다. 재구성은 완료 시점의 상태(후결 대기)로 되살린다. ② 마지막 덤프 이후 **진행 중인 문서**는 S3에 본문 리비전만 있어 복구되지 않는다(DB RPO 24시간). ③ 수명 주기·Object Lock·`rclone`·컨테이너 안 Chromium 같은 배포 환경 기능은 이 PC에서 검증하지 못했다.

**Considered Options:** 덤프를 계정 소유자에게 열기(모든 계정 데이터 노출), 서버에 개인키를 두고 화면에서 복호화(서버 침해 시 전부 노출), age 바이너리를 이미지에 포함(개발 PC 테스트가 어렵고 스트림 연동이 번거로움), 변경 토큰을 WAL LSN으로(pg-boss 하트비트가 계속 올림), 내보내기 URL을 7일 유효로(유출 위험), 색인 재구성에 `SECURITY DEFINER` 우회 함수(불변 트리거를 약화시킴 — 앱 역할로 만들어진 순서를 재현하면 필요 없다), 첨부를 ZIP마다 복사(저장·시간 2배, 참조로 충분).
