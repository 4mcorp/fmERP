# API 규칙 (Hono)

기준: [PRD 5.3 권한 · 5.12 API](../PRD.md) · [rules/security.md](./security.md)

## 1. 위치와 정의
- Hono 앱은 `apps/web/server/`에 두고, `app/api/[[...route]]/route.ts`에서 마운트한다.
- 라우트는 `@hono/zod-openapi`로 정의한다. 요청과 응답 스키마는 Zod로 작성하고, 같은 스키마를 프런트 폼 검증에도 재사용한다.
- 입력 검증은 API 경계에서 한 번 한다. 그 안쪽(core, db)은 검증된 타입을 받는다.

## 2. 미들웨어 순서
1. 요청 ID 부여
2. 세션 인증 (Better Auth)
3. 테넌트 컨텍스트 설정 (`account_id`)
4. 권한 확인 (역할 + 범위, PRD 3.2·PERM-001)
5. 핸들러
6. 감사 로그 기록 — 상태 변경 요청, 민감 정보 조회·다운로드 (PRD AUD-020·021)

## 3. 필수 규칙
| 규칙 | PRD |
|---|---|
| 결재 처리, 백업·내보내기 다운로드, DB 덤프, PIN 변경은 **재인증(결재 PIN)** 을 요구한다 | AUTH-009, BAK-006·009 |
| 결재 처리 API는 멱등 키를 받는다. 같은 키로 다시 요청하면 같은 결과를 돌려준다 | APV-045 |
| 파일은 API가 직접 내려주지 않는다. 권한을 확인한 뒤 **짧은 수명의 서명 URL**만 발급한다 | FILE-004 |
| 완료된 문서를 수정하려는 요청은 거부한다 (409) | APV-062 |
| 이메일 링크만으로 결재가 승인되면 안 된다. 반드시 로그인과 재인증을 거친다 | NTF-006 |

## 4. 미정
에러 응답 형식은 골격 생성 시 ADR로 확정한다 ([architecture.md 4장](./architecture.md)).
