## 증상 1 — 감사 열람 기록 중복
- 감사인이 문서 상세를 한 번 열었는데 이력에 "감사 열람"이 같은 시각에 4건 나왔다 (10분 중복 억제가 있는데도). 개발 서버에서 직접 열어 보고서야 알았고, 통합 테스트는 처음에는 통과했다(요청 수가 적어 경합이 안 걸림).

## 원인 1
- 화면 하나가 여러 API(상세·본문·의견·이력·양식·패키지·첨부)를 **동시에** 부른다. 각 요청이 별도 트랜잭션에서 "최근 기록 있나?" 확인 → 없음 → 기록을 하므로, 확인과 기록 사이가 겹쳐 모두 "없음"을 본다. 로그는 UPDATE할 수 없어 기록 후 정리도 못 한다.

## 해결 1
- 같은 사용자·문서 조합마다 `pg_advisory_xact_lock(hashtextextended('audit_view:사용자:문서', 0))`로 확인~기록을 직렬화했다(트랜잭션 끝에 자동 해제). 테스트는 28개 요청을 동시에 보내 정확히 1건인지 본다(처음에 10건으로 재현됨).

## 증상 2 — 통합 테스트 25건 실패
- 전체 `pnpm test:int` 직후 `approval-m4` 등에서 "문서 생성 실패"가 25건 났다. 단독 실행은 통과.

## 원인 2
- 앞서 `( … ; pnpm test:int ; …) &`로 **백그라운드에 걸어 둔 통합 테스트가 계속 돌고 있었고**(`unit.log`·`int.log`가 늦게 생겨 안 도는 줄 알았다), 같은 시각에 전경으로 또 돌려 **같은 시험 DB에 두 벌**이 겹쳤다. 시험은 계정·PIN·문서 상태를 공유한다.

## 증상 3 — worker 큐 테스트 시간 초과
- `package-jobs.int.test.ts`가 20초 시간 초과로 실패. 로그에는 이미 지워진 문서 ID의 "패키지 생성 실패"가 가득했다.

## 원인 3
- pg-boss 전용 스키마(`pgboss_test_worker`)에 **이전 실행의 작업이 남아** 지워진 문서를 가리키며 계속 재시도했다. 스윕은 다른 테스트 파일이 만든 완료 문서까지 집으므로(그 문서도 곧 지워짐) 전체를 병렬로 돌리면 더 심해진다. 대기 한도(30초)가 vitest 시간 제한(20초)보다 길어 기다리기도 전에 끊겼다.

## 해결 3
- `beforeAll`에서 워커를 붙이기 **전에** `boss.deleteAllJobs()`로 큐를 비운다(워커가 폴링 중일 때 하면 교착). 두 테스트의 제한을 60초, `waitFor`를 50초로 맞췄다.

## 재발 방지 규칙
- 여러 API를 동시에 부르는 화면에서 "확인 후 기록"(중복 억제, 한 번만 쓰기)은 **advisory lock으로 직렬화**하고, 동시 요청 테스트(수십 건)로 고정한다. 새로고침 한두 번으로는 경합이 재현되지 않는다.
- **개발 서버에서 직접 열어 이력·로그를 확인**한다. 자동 테스트가 통과해도 동시성 결함은 숨는다.
- 테스트(특히 통합·E2E)를 백그라운드로 걸었으면 끝났는지 확인하기 전에는 같은 DB에 다른 테스트를 돌리지 않는다. 백그라운드 체인은 쓰지 않는다(단위 → 통합 → E2E 순서로 전경에서 하나씩).
- 통합 테스트가 공유 큐·스키마(pg-boss 등)를 쓰면 시작할 때 이전 실행의 잔여물을 비우고, 대기 한도는 테스트 제한시간보다 짧게 둔다.
