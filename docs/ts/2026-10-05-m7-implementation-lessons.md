## 1. 키셋 커서가 시각을 밀리초로 잘라 무한 반복 (재발)
- **증상:** 계정 내보내기가 감사 로그 JSON에서 멈췄다(2,100건을 넣은 시험, 같은 쪽을 무한히 다시 읽음). 로그를 찍어 보니 `audit page 2000`이 끝없이 반복됐다.
- **원인:** 커서에 JS `Date`(밀리초)를 넣어 `occurred_at = 커서` 비교가 맞지 않았다. DB 시각은 마이크로초라, 한 문장에서 만든 같은 시각의 행이 쪽마다 다시 읽혔다. **M5 문서함에서 고친 것과 같은 유형**이다(M5 plan 결정·변경 기록의 "커서가 시각을 밀리초로 잘라" 항목).
- **해결:** 커서는 `to_char(... 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"')` 문자열로 들고 `::timestamptz`로 비교한다.
- **규칙:** 키셋 커서에 시각을 쓰는 곳은 **같은 시각의 행이 2,000건 넘게 있는 시험**을 둔다. 새 목록을 만들 때 M5 문서함·M6 감사 로그·M7 내보내기와 같은 방식(마이크로초 문자열)을 쓴다.

## 2. 다른 시험이 남긴 가짜 상태가 내 시험을 흔듦 (전체 실행에서만 실패)
- **증상:** 단독·쌍으로는 통과하고 전체 통합 테스트에서만 실패했다. ① `owner-b`의 활성 회사가 달라 내보내기 이력이 어긋남 ② 복구 리허설이 다른 시험이 만든 "객체 없는 READY 패키지"를 실패로 보고 ③ M1의 PIN 시험이 `owner`에게 PIN이 이미 있다며 실패.
- **원인:** 시험 DB·S3는 한 번 초기화되면 파일들이 공유한다. 내가 만든 시험이 가짜 행(객체 없는 READY 패키지), 설정한 PIN, 바꾼 S3 객체를 남겼다.
- **해결:** 시험이 만든 가짜 상태는 **그 시험이 끝날 때 치운다**(트리거를 소유자 권한으로 잠시 끄고 삭제, PIN 삭제, 바꾼 객체 복원). 슬러그로 회사를 찾지 말고 **세션의 활성 회사**를 쓴다. 다른 시험의 상태에 기대는 단언은 "내 문서가 통과했다"처럼 자기 것에 한정한다.
- **규칙:** 통합 테스트 파일은 끝날 때 자기가 만든 **가짜 상태·PIN·바뀐 객체를 원래대로** 돌린다. 전체 실행을 **연속 2회** 통과시켜서 안정성을 확인한다. (리허설이 가짜 패키지를 정확히 잡아낸 것은 기능이 제대로 동작한다는 뜻이기도 하다.)

## 3. 커밋이 조용히 실패
- **증상:** 한 묶음의 커밋이 안 됐는데 `git commit ... | tail -1`의 마지막 줄만 보고 성공으로 착각했다. 나중에 `git status`에 스테이징된 채 남은 파일이 보였다.
- **원인:** pre-commit(biome)·commitlint가 실패하면 출력의 앞쪽에 오류가 있고 마지막 줄은 요약이다. `tail -1`이 오류를 가렸다.
- **규칙:** 커밋 결과는 **`git log --oneline -1`로 새 커밋이 생겼는지 확인**한다. 커밋 출력은 자르지 않거나 끝 여러 줄을 본다. (기존 규칙 "린트·테스트 출력을 `tail`로 자르지 않는다"와 같은 뿌리.)

## 4. 프로세스를 이름 패턴으로 종료해 다른 프로세스까지 죽임
- **증상:** 임시로 띄운 worker를 끄려고 `Get-CimInstance Win32_Process | Where CommandLine -like '*src/main.ts*'`로 찾아 종료했는데 9개가 종료됐고, 3000(개발 서버)·3001(기존 worker) 포트가 함께 내려갔다.
- **원인:** 패턴이 넓었다. 내가 띄운 것(포트 3011)만 가려내지 않았다.
- **규칙:** 프로세스를 끌 때는 **내가 띄운 PID**(백그라운드 작업 ID나 포트의 `OwningProcess`)만 종료한다. 종료 전에 대상 목록을 출력해 확인한다. 기존에 떠 있던 프로세스를 죽였다면 사용자에게 알린다.

## 5. 계정 설정 저장이 항상 400 (Radix Select의 빈 값)
- **증상:** 관리 콘솔 계정 설정에서 어떤 항목이든 저장하면 `maxDeptDepth: Too small` 400. M2부터 있던 결함이라 자동 테스트에 이 경로가 없었다. 내보내기 허용 토글을 E2E로 저장하다 발견했다.
- **원인:** Radix Select가 값이 바뀔 때 숨은 `<select>`로 빈 값(`""`)을 보내 `onValueChange("")`를 부르고, 폼이 `maxDeptDepth`를 `Number("")=0`으로 보냈다.
- **해결:** `onValueChange={(v) => v && set("depth")(v)}`로 빈 값을 무시한다. E2E가 저장 경로를 덮는다.
- **규칙:** 폼에 Radix Select를 쓰면 **빈 값 변경을 무시**하고, 화면의 저장 버튼 경로는 E2E로 한 번 눌러 본다(타입·API 테스트만으로는 못 잡는다).
