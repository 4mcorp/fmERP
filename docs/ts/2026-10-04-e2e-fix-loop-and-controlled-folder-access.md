## 증상
- plan 승인 후 구현에 약 63분(173턴)이 걸렸고 사용자가 중단했다. 도구 실행 약 30분, 모델 시간 약 32분.
- 마지막 약 20분은 E2E 실패(`복구`·`PIN 재인증` 테스트)를 로케이터·모달 라벨 수정으로 반복해서 고쳤다.
- `biome check`가 EPERM으로 실패해 `sleep 3` 재시도 루프(최대 5회, 1회 약 2분)를 썼다.
- 커밋 시 Windows 보안에 "보호된 메모리 액세스 차단됨 (sh.exe, 제어된 폴더 액세스)" 알림이 다수 발생했다.

## 원인
- 한 번에 맡긴 범위가 M4 전체였고 중간 확인 지점이 없었다.
- 수정마다 `biome` → `typecheck` → 전체 `test:e2e`(약 100초, 실패 시 30초 타임아웃 대기)를 모두 다시 돌렸다.
- 실패 원인이 한 곳이 아니었다(`rich-text` 제목 라벨 중복, 모달 접근성 이름, 로컬 복구 배너). 하나를 고치면 다음 실패가 나왔다.
- Windows 제어된 폴더 액세스가 `sh.exe`(Git Bash, lefthook 훅·에이전트 Bash 도구)의 쓰기를 막은 것이 확인됐다. biome EPERM과의 연관은 **추정**이며 차단 기록으로 검증하지 못했다.

## 해결
- 실패한 파일·프로젝트만 돌려 확인했다: `playwright test e2e/m4.spec.ts --project=desktop|mobile`.
- 마지막에 전체 E2E를 한 번만 돌렸다(24 통과, 3 건너뜀).
- 보안 설정은 사용자 몫이다. 필요하면 "제어된 폴더 액세스를 통해 앱 허용"에 `sh.exe`, `node.exe`를 추가한다.

## 재발 방지 규칙
- E2E가 실패하면 **실패한 테스트만**(`-g`, 파일, `--project`) 다시 돌린다. 전체 `test:e2e`는 단계 끝에 한 번만 돌린다.
- 린트·타입 검사는 수정 묶음마다가 아니라 단계가 끝날 때 한 번 돌린다.
- 같은 실패가 3번 반복되면 멈추고 원인(여러 곳인지)을 보고한 뒤 방향을 정한다.
- 큰 plan은 화면·기능 단위로 쪼개 중간에 커밋하고 사용자에게 진행을 알린다.
- `biome`·`git` 등이 EPERM으로 실패하면 재시도 루프를 쓰지 말고 Windows 차단 기록(제어된 폴더 액세스, 백신 잠금)을 먼저 사용자에게 확인한다.
